# Phone demo: a room remembers, then acts

Keep the phone on the visitor chat and a laptop on `/demo/maintenance?ticket=P-202`.
The seeded history is synthetic; describe it as demo history.

1. Tap the NFC chip, press Continue, and show **Pitch Area** and **Secure NFC scan checked**. Only use that phrase if the badge actually appears.
2. Turn on the speaker icon. Pip gives a short greeting. Voice uses cached cues, not spoken versions of every answer.
3. Type **“The right projector keeps going black.”**
4. Point to P-202: an unresolved report from two days ago, with the replacement cable note. Say: **“The room remembers this issue, so SIGNAL can update the existing ticket instead of creating a duplicate.”**
5. Approve **Add my report to P-202 and escalate**. Pip explains it is starting the form update. The visitor never needs maintenance contact details.
6. Watch Anchor work on the owned portal. When the phone shows VERIFIED, refresh the laptop portal and point to the new report note and reference. Say: **“A click isn’t enough. SIGNAL checks the saved record before confirming the update.”**
7. Optional: approve the separate maintenance call while holding the pre-approved receiving phone. It reads a brief automated report. A completed call is not a human acknowledgement. The ten-minute ticket cooldown prevents repeated calls.

Close with: **“One tap gives this space a memory and a way to act—with the visitor’s approval and a record of what happened.”**

Rehearse the Anchor step before presenting; a manual portal save test does not prove the live browser agent works. If verification fails, show the actual pending/error state. Use a clearly labelled recording as backup.

For a second, quick self-service example, try **“My laptop shows no signal on the left projector.”** The seeded resolved report records switching the laptop to Duplicate display mode. Pip should offer a sourced safe step rather than immediately escalate.
